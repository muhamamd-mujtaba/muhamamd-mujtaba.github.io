## Beginning My First Database Project

One of the most memorable experiences of my second semester was building my first Database Systems project. Until that point, I had studied many theoretical concepts such as entities, relationships, normalization, primary keys, foreign keys, and SQL queries. Although I understood the theory, I had never experienced how all these concepts work together in a complete database project.

After strengthening my understanding of Database Systems following my mid examinations, I felt ready to apply my knowledge in a practical project. This project became an opportunity to test everything I had learned throughout the semester.

Instead of thinking about marks, I wanted to challenge myself by designing a database that followed proper rules and reflected real-world requirements.

## Planning Before Writing SQL

The first lesson I learned was that a successful database project begins with planning rather than coding.

Before creating any tables, I carefully thought about the information that needed to be stored. I identified the entities involved, listed their attributes, and decided how different tables would be connected.

This planning stage helped me understand that database design is similar to building a house. Without a strong foundation, problems appear later during implementation.

Taking time to think before writing SQL saved me from many mistakes during the later stages of the project.

## Designing Tables Carefully

The next step was designing the database tables.

At first, I believed creating tables would be the easiest part of the project. However, I soon realized that every table must have a clear purpose.

I carefully selected appropriate column names, data types, and primary keys for each table. I also made sure that duplicate information was minimized by applying the normalization concepts I had learned during the semester.

As I continued working, I realized that a well-designed table makes every future operation much easier.

## Understanding Relationships Between Tables

One of the most interesting parts of the project was creating relationships between different tables.

Earlier in the semester, primary keys and foreign keys seemed like simple definitions from the textbook. During the project, I finally understood why they are so important.

By connecting related tables through foreign keys, I avoided unnecessary duplication of information and maintained consistency throughout the database.

This practical experience made relationship design much easier to understand than reading theoretical examples alone.

## Applying SQL in Real Situations

Once the database structure was complete, I started writing SQL queries.

I created tables using CREATE TABLE statements, inserted records with INSERT INTO, retrieved information using SELECT queries, updated records through UPDATE statements, and removed unnecessary information using DELETE commands.

I also practiced aggregate functions such as COUNT(), SUM(), AVG(), MAX(), and MIN() whenever appropriate.

Writing SQL in a real project felt completely different from solving classroom exercises because every query had a practical purpose.

## Solving Problems During Development

Like every beginner, I also faced several problems while developing my database project.

Sometimes I forgot commas between columns while creating tables. On other occasions, incorrect data types caused errors. I also experienced foreign key constraint issues when inserting records in the wrong order.

Instead of becoming frustrated, I carefully read every error message and tried to understand the reason behind it.

Each mistake became a valuable lesson. Gradually, I noticed that debugging errors improved my SQL knowledge more than simply reading theory.

By solving one problem after another, my confidence increased significantly.

## Revising Normalization During the Project

While building the project, I repeatedly revisited normalization.

Initially, some tables contained duplicate information. After reviewing the database carefully, I reorganized the structure according to First Normal Form, Second Normal Form, and Third Normal Form.

This process reduced redundancy and improved the overall organization of the database.

Applying normalization in a real project helped me appreciate its practical value. It was no longer just a chapter from the textbook; it became an essential part of building a professional database.

## Skills I Developed During the Project

Completing my first database project improved many of my technical skills.

I became more confident in writing SQL queries and understanding relationships between tables. My knowledge of normalization became stronger because I applied it practically instead of simply revising notes.

I also improved my problem-solving skills. Every error forced me to think logically and find a solution rather than giving up.

Most importantly, I learned that software development is an iterative process. No project becomes perfect in the first attempt. Continuous improvement is always part of technical work.

## Looking Toward Future Projects

Completing my first Database Systems project gave me the confidence to work on larger technical projects in the future.

I now want to explore advanced SQL topics such as joins, views, stored procedures, indexing, transactions, and database optimization. I also hope to connect my database knowledge with web development, Artificial Intelligence, and Machine Learning, where organized data plays a vital role.

This project also motivated me to continue documenting my learning journey on GitHub. Instead of uploading only source code, I now understand the value of explaining what I learned, the challenges I faced, and the solutions I discovered during development.

Looking back, my first database project was much more than a university assignment. It became an experience that transformed theoretical knowledge into practical skills. It strengthened my confidence, improved my logical thinking, and inspired me to continue learning Database Systems with greater enthusiasm. I believe this project is only the beginning of a much longer journey in software development and data management.
